# Python SDK 使用指南

[English](https://github.com/tansrai/tansr-python/blob/main/doc/guide.md) · [项目入口](https://github.com/tansrai/tansr-python/blob/main/README.md)

本指南对应 `0.1.0` SDK 和三个 Demo；两包均采用 [MIT 许可证](https://github.com/tansrai/tansr-python/blob/main/LICENSE)，通过 PyPI 分发。安装方式、已验证环境和平台限制见 [发行说明](https://github.com/tansrai/tansr-python/blob/main/doc/%E5%8F%91%E8%A1%8C%E8%AF%B4%E6%98%8E.md)。

## 安装和职责

运行源码支持 CPython 3.7+，排除 3.9.0/3.9.1。旧版本兼容不恢复解释器的上游维护。SDK 通过统一 `/api` 消费 Serve；运行循环、上下文、记忆、权限和工具调度归 Serve。Python 宿主负责身份、明确注册的业务工具与本地档案，不包含通用 Shell/PTY、录音播放或多设备同步。

在虚拟环境中执行 `python -m pip install tansr-sdk==0.1.0`；需要 Demo 时再执行 `python -m pip install tansr-sdk-demo==0.1.0`。离线环境可安装已核验的同版 wheel，替换下面的绝对路径；Demo 精确依赖同版 SDK，不得混用不同版本：

```text
python -m pip install /absolute/artifacts/tansr_sdk-0.1.0-py3-none-any.whl /absolute/artifacts/tansr_sdk_demo-0.1.0-py3-none-any.whl
python -m pip check
tansr-py-chat --help
tansr-py-tools --help
tansr-py-archive --help
```

三个模块入口是 `python -m tansr_demo.chat`、`python -m tansr_demo.tools` 和 `python -m tansr_demo.archive`。`--help` 不读取凭据、不联系 Serve。源码构建在准备好的现代环境中，于仓根执行 `python -m build --wheel --sdist` 和 `python -m build --wheel --sdist demo`。依赖锁及独立 wheel/sdist 消费门见 [环境说明](https://github.com/tansrai/tansr-python/blob/main/requirements/README.md)；源码可导入、构建成功和独立安装消费分别验收。

Demo 不启动或下载 Serve。宿主须先配置 Serve、模型提供方、终端身份及需要的档案 source。默认合同族是 `sdk1`；使用 offload 时每个相关命令均显式带 `--family sdk2-offload-v1`。

### 应用接线

SDK 与 Demo 分包：自己的服务、桌面程序或 asyncio 应用只需要 `tansr-sdk`。`tansr-sdk-demo` 是独立参考应用，不是 SDK 的凭据或状态层依赖。已准备好依赖 wheelhouse 时，可离线安装已核验的同批包；仓外空 venv、完整解释器路径及校验清单的用法见发行说明。

| 层 | 谁负责 | 接线方式 |
| --- | --- | --- |
| 核心与服务 | Serve 宿主 | 配置模型、应用能力、会话/权限、上下文/记忆及档案 Source |
| 身份 | 开发者的认证服务与应用 | `token_provider(cancel)` 返回 `AuthToken(token, principal)`；principal 表达稳定且可信的应用/用户/授权边界 |
| 会话 | Python SDK | `SessionClient(api)` 或 `AsyncSessionClient(api)`；创建/attach/resume 后使用同一 ID |
| 设备业务 | Python 宿主 | 明确工具声明、handler、当前授权检查、`FileJournal` 和 `Runner` |
| 本地长历史 | Python 宿主与 SDK | `FileStore` 验证并耐久保存 Source 档案；`ArchiveClient` 对账 ACK、按需供材 |

普通控制操作走 HTTP，事件走 SSE；当前接线不要求 WebSocket。持续事件流不能用一次 HTTP 受理回执代替。服务地址应是 Serve 的 origin，例如 `https://serve.example.com`；不要把 `/api` 追加到 `Client` 的 base URL，SDK 使用冻结操作路径，也不跟随重定向跨站携带凭据。

| 会话族 | 创建与恢复 | 存储边界 |
| --- | --- | --- |
| `sdk1`（默认） | `SessionClient.create()`；`attach(id)` 只观察，`resume(id)` 明确重建/恢复；创建选项不接受 offload `request_id` | 保留 Serve 原完整存储和检查点能力；是否允许具体功能仍由当前服务返回 |
| `sdk2-offload-v1` | 新建必须保存 `CreateOptions(request_id=...)` 的原意图；恢复使用原 ID，不支持 `fork` | 需要 Serve 已配置授权 Source；创建内部带出绑定，不人工制造未绑定窗口 |

family 固定在 `Client` 上。使用另一个族读取或恢复原会话会被拒绝，不自动降级、迁移或创建替代会话。换用户时建立新的 Client 与该用户的资源集合；一个 Client 不得通过换 token 混用不同 principal。同一 principal 的短 token 可续期，SDK 每次发送仍调用 provider。provider 必须检查取消、使用有界等待，不能在其中阻塞等待它所属的 Client 关闭。

## 凭据和共用参数

token 与 scope 是同一私有目录中的两个不同文件，参数必须为不含 `.` / `..` 路径段的绝对路径。scope 内容严格只有以下三项，值为宿主签发、非空且不超过 128 字符的字符串；不要自行猜测身份：

```json
{"applicationScopeId":"issued-application","endUserId":"issued-user","authorizationRevision":"issued-revision"}
```

凭据目录必须与事务状态根分开。例如 token/scope 放在 `tansr-demo-credentials/`，创建/材料意图和档案放在另外的 `tansr-demo-state/`，工具 journal 使用 `tansr-demo-journal/`。`--prepare-create`、`--create-intent`、`--intent`、`--file` 的父目录以及 `--journal` 本身都不能是凭据目录。Demo 在建立 Client 前报 `credentials_state_overlap`，不等到原生目录锁冲突；此约束保留每次存储操作对当前 scope 的重新核验，不缓存授权或弱化底层验证。

使用公开存储 API 创建受保护目录和文件。例如将下面保存为本地脚本运行，输入宿主已签发的信息；父目录须已存在，已有文件不会被覆盖：

```python
from getpass import getpass
from pathlib import Path
from tansr_sdk import strict_json
from tansr_sdk.storage import PrivateDirectory

path = Path.home() / "tansr-demo-credentials"
scope = {key: input(key + ": ") for key in
         ("applicationScopeId", "endUserId", "authorizationRevision")}
token = getpass("Issued Serve token: ").encode("ascii")
with PrivateDirectory(str(path), create=True) as directory:
    directory.write("scope.json", strict_json.dumps(scope), replace=False)
    directory.write("token", token, replace=False)
```

PowerShell 示例：

```powershell
$env:TANSR_BASE_URL = 'http://127.0.0.1:8787'
$env:TANSR_TOKEN_FILE = 'C:\Users\YOUR_USER\tansr-demo-credentials\token'
$env:TANSR_SCOPE_FILE = 'C:\Users\YOUR_USER\tansr-demo-credentials\scope.json'
```

Linux/macOS 示例：

```sh
export TANSR_BASE_URL=http://127.0.0.1:8787
export TANSR_TOKEN_FILE="$HOME/tansr-demo-credentials/token"
export TANSR_SCOPE_FILE="$HOME/tansr-demo-credentials/scope.json"
```

| 参数 | 默认与含义 |
| --- | --- |
| `--base` | `TANSR_BASE_URL`，否则 `http://127.0.0.1:8787` |
| `--family` | `sdk1`；另选 `sdk2-offload-v1` |
| `--token-file` / `--scope-file` | 对应环境变量；两者都必需 |
| `--ca-file` | 可选受信 CA PEM 绝对路径，仍验证 TLS |
| `--timeout` | 整个本地 Demo 生命周期，默认 600 秒，范围 1..86400 |
| `--request-timeout` | 普通控制请求默认 30 秒，范围 1..86400 |

默认 `HttpTransport` 在 HTTPS 的 DNS 查询/连接之前校验当前 stdlib SSL 运行时。最低识别范围为 OpenSSL 1.1.1n+ 的 1.x 分支、3.0.2+ 的 3.x 分支；更早版本以及未经验证的其他 provider 会抛 `unsupported_tls_runtime`，没有关闭检查的参数。此门针对已知证书解析风险，不代表旧 OpenSSL 恢复上游维护；cryptography 使用的另一份 OpenSSL 也不能替代 stdlib SSL 的判据。

Windows 官方 CPython 3.7.9 携带 OpenSSL 1.1.1g，默认 HTTPS 因此受限；其连接前拒绝证据继续保留，不能拿回环 HTTP 成功替代 TLS 正向。本轮另行验证了独立 prefix 中的 Anaconda CPython 3.7.9 `h60c2a47_0` + OpenSSL 1.1.1w `h2bbff1b_0`：同 SDK wheel 安装后默认信任 HTTPS 200、CA/主机名/过期拒绝、真实握手和 SSE 取消/期限均通过。此结果只属于该组合，不外推为所有 Python 3.7 环境通过。

最低 Python 版本与 SSL 运行时安全基线分开核对。上述隔离 3.7.9 路线的官方来源、固定包/SHA、安装与 `micromamba run -p ... python` 用法见 [发行说明](https://github.com/tansrai/tansr-python/blob/main/doc/%E5%8F%91%E8%A1%8C%E8%AF%B4%E6%98%8E.md)。它解决该版本的实际兼容接入，不恢复 Python 3.7 或 OpenSSL 1.1.1 的上游维护；新应用优先选择受维护的现代解释器。宿主也可显式注入独立验证的安全传输，Demo 没有这种替换开关。不要覆盖系统 Python DLL 或关闭证书验证；`--ca-file` 不承诺在指定 CA 文件外额外保留所有系统根，也不绕过 guard。

使用隔离 prefix 时，SDK 子进程和新建 venv 也必须继承该 prefix 的 DLL 搜索路径。本轮某些上下文中仅 `micromamba run` 的首进程可载入 SSL，孙进程 PATH 却缺 `Library/bin`；发行说明提供经过验证的进程级启动方式，只向 child env 补齐路径，不修改全局 PATH。不要裸运行 prefix/python.exe，或复用由旧解释器建立的 venv 来判断新 SSL 已生效。

macOS 还要核对 Python 构建实际提供的目录描述符能力。已发现 Conda CPython 3.7.12 的 macOS 10.9 target 构建虽然能使用 TLS，但 `os.supports_dir_fd` 为空、所需 `*at` 构建能力缺失，不能使用 SDK 私有目录/档案/journal；不能仅按 `3.7+` 版本号认定完整支持。SDK 不降级成裸路径访问。替代的官方 CPython 3.7.17 **源码**已在 x86_64、target 10.13 下本地隔离构建成功，链接隔离 OpenSSL 1.1.1w；目录能力、SDK/Demo sdist 安装、完整单元、默认 HTTPS、两族真实异步会话和 Demo 验收均已通过。这是本地 Rosetta 构建，不是官方二进制发行或原生 arm64 的 3.7 环境，精确范围见发行说明。

新解释器保留对原 OpenSSL prefix 的链接依赖。原 Conda 解释器不适用于 SDK 私有存储，并不意味着可删除其中被新构建引用的 OpenSSL 动态库。保留 runtime、它所依赖的 OpenSSL prefix 和由它新建的 venv；不要只复制 venv/python 文件，或因旧解释器验收失败而清理仍被加载的依赖。

Demo 每次取 token 和访问私有状态时核对当前 scope。scope 变更使旧实例失败，旧档案不能恢复权限；同一 scope 下可以轮换 token。恢复意图保留原绝对截止，延长新进程 `--timeout` 不会延长原请求。Ctrl+C 停止本地工作；只有显式 `/interrupt` 才请求远端中断。

退出 0 仅表示该命令声明的阶段成功，退出 1 为运行失败、取消或结果未知；参数错误退出 2，直接捕获的 `KeyboardInterrupt` 退出 130。Host 的 Ctrl+C 通常转为取消并退出 1。错误只显示安全错误码和 HTTP 状态，不打印 token、服务端 detail 或异常链；会话文本及显式查询内容会显示在终端。

## 会话 Demo

```text
tansr-py-chat --message "你好"
tansr-py-chat --attach SESSION_ID
tansr-py-chat --resume SESSION_ID
```

不提供 `--message` 时交互运行。`--attach` 只接入；`--resume` 明确调用恢复。两者与下文的两个创建意图模式互斥；接入/恢复不接受 `--model` 或 `--request-id`。新建可选 `--model`；offload 新建必需稳定 `--request-id`，sdk1 禁止该参数。`--last-event-id` 是原交付的十进制字符串游标，不是 turn ID 或档案覆盖水位。

发送前先建立 SSE。Demo 只根据本轮匹配的终态判成功，202、EOF、旧轮完成事件均不代表新轮成功。正在运行的会话拒绝 `--message`；交互接入读取可信当前 turn，必要时从 0 完整重放，不能用任意非零游标代替。重放 gap、无终态断流、失败或中止都以非零退出，需核对原会话；不会自动换会话或重发消息。

| 交互输入 | 行为 |
| --- | --- |
| 普通文本 | 仅在会话 idle 时发送新轮 |
| `/interrupt` | 发送远端中断请求；受理后继续等待终态 |
| `/allow TICKET` / `/deny TICKET` | 仅答复当前实际观察到、尚未关闭的权限票据，携带原 digest |
| `/answers TICKET JSON_ARRAY` | 答复当前提问；每项包含 `questionId`，可有 `selectedOptionIds`、`freeText` |
| `/target` | 查询当前输入能力与可信 target |
| `/insert JSON_OBJECT` | 提交原 `inputId`、`target`、`content.text`，可选 `ack`；ACK 不证明已消费 |
| `/history` | 调用 `history(0, 0)` 查询历史摘要/计数 |
| `/quit` | 结束本地观察，不发远端中断 |

输入示例中的 `historyEpoch`、`turnId` 须来自刚查询的真实 target，不可照抄：

```text
/insert {"inputId":"my-original-input","target":{"historyEpoch":"REAL_EPOCH","turnId":"REAL_TURN"},"content":{"text":"补充说明"}}
```

非交互模式遇权限/提问会保留会话并非零退出，提示交互接入同一个 ID。内联工具请求不会被自动执行；需要下节明确注册的 executor。

### Offload 创建失回

先保存原创建意图，再使用同一私有文件提交：

```text
tansr-py-chat --family sdk2-offload-v1 --request-id create-one --prepare-create ABSOLUTE_PRIVATE_FILE --timeout 600
tansr-py-chat --family sdk2-offload-v1 --create-intent ABSOLUTE_PRIVATE_FILE
tansr-py-chat --family sdk2-offload-v1 --attach RETURNED_SESSION_ID --message "你好"
```

`--prepare-create` 不创建会话；`--create-intent` 保留原 body、requestId、requestKey、截止与身份，打印会话 ID 后退出，不发送轮次。这两个模式不接受 message/cursor；提交已存意图不能另给 model/requestId。失回后在原截止内重用原文件；到期保留未知状态，不生成新 ID 冒充恢复。sdk1 没有此 requestId 恢复合同；未知创建不可盲目重试。

## 业务工具与实时输出 Demo

```text
tansr-py-tools --journal ABSOLUTE_PRIVATE_DIRECTORY --require-output --run-once
```

新 offload 会话另加 `--family sdk2-offload-v1 --request-id tools-one`。`--executor` 默认 `python-demo`。`--session SESSION_ID` 接入预先声明同一 `DemoOrderStatus` 工具的会话，不能同时传 request-id。Demo 刷新能力闭包、初始化并绑定 executor，要求工具实际可用；不会替用户修改已有会话声明。

看到 `ready` 后，在另一个终端执行提示的 chat attach 命令，请求查询订单 `DEMO-001`。工具只返回演示订单“待发货”，其他订单为确定的业务错误，不能作为真实订单服务。若使用仓内确定性模型 fixture，其专用触发词 `GO-TOOL` 仅属于验收 fixture，不是 SDK 通用语法。

`--require-output` 要求输出协商与 seal ACK。handler 先写 stdout 首块，合作等待 0.75 秒，再写 stderr，首块在业务结束前发出；不替换进程全局 stdout/stderr。输出后取消保留 unknown，不能宣称没有副作用。Runner 负责续租、当前授权、原 claim 与业务回执耐久记录；不将 stdout seal 成败改写成业务结果。

`--run-once` 等待一个实际提交的业务回执后结束，空轮询不算成功。业务回执非 completed 或输出未确认均非零退出；保留原 journal，不能重跑 handler 来修补 seal。长期模式持续接任务，Ctrl+C 仅停本地 executor。

### 在自己的应用中注册工具

沿用 [tools Demo](https://github.com/tansrai/tansr-python/blob/main/demo/src/tansr_demo/tools.py) 的装配顺序：`Tool(declaration, handler)` → `Tool.registration()` → `ExecutorClient.register()` → `initialize()` / `bind()` → 可选 `negotiate_output()` → `Runner`。初始化声明当前平台；实际有效工具和绑定必须由服务确认，不能把本地支持的工具列表当成已经获授权。Demo 使用当前能力闭包；不要从旧日志复制 closure、binding 或 connectionRevision。

handler 形状为 `handler(context: ToolContext, arguments: dict)`。`context.check()` 检查原截止和合作取消；已协商输出时可调用 `context.output.capture("stdout", b"...")` 或相应 stderr 字节通道。工具声明和普通业务 JSON 使用自身合同，不能用控制 canonical 对业务浮点数强制改写；同一操作的输出 sequence、UTF-8 原字节和摘要由 SDK 维护。

成功工具结果使用 `{"status":"ok","content":[{"t":"text","text":"..."}]}`；确定的业务错误可返回 `{"status":"error","message":"..."}`。`Rejected(code)` 只适用于宿主能确认无副作用的拒绝。普通异常、无效结果或取消后的不明副作用必须保留 unknown，不能用 catch-all 假装没有执行。`ExecutionOutcome.receipt`、`output_confirmed` 与 `output_error` 分开读取；输出失回通过原状态/原块对账，不重新执行业务函数。

`adapt_async_handler` 在该 handler 自有工作线程的独立 loop 中运行异步函数，不接管应用主 loop。普通同步 handler 仍须合作检查 `context`；SDK 无法强杀任意 Python 线程。业务授权回调、handler 和 on_receipt 都不能用无限阻塞换取“同步完成”。

journal 中的 `demo-session.intent.json` 在创建前保存原 body/key/deadline，`demo-session.result.json` 保存已知 ID。重启原目录接入原 ID；offload 创建失回重用原意图，sdk1 仅有待定意图时拒绝再创建。sdk1 如已从可信渠道找回原 ID，可显式 `--session` 接入并保存结果。不要删除 journal 或换目录“恢复”原操作。

## 本地档案 Demo

档案 source 的注册和身份由 Serve 宿主负责。先用 `target` 读取真实目标；offload 已绑定时不能强制当成未绑定重新创建。sdk1 手动创建使用 prepare/create 两步。

| `--mode` | 必选专用参数 | 成功阶段 |
| --- | --- | --- |
| `target` | `--session` | 查询 binding target |
| `prepare-create` | `--session --source --request-id --intent` | 原绑定意图已保存，未创建 |
| `create` | `--intent` | 提交原意图并返回 binding ID |
| `creation-status` | `--intent` | 原创建操作状态为 completed |
| `status` | `--binding` | 查询 state/publishedThroughSequence/acknowledgedCoverage |
| `sync` | `--binding --file --key-id` | 所有页同步完成；可选 `--max-pages` |
| `recover` | `--binding --file --key-id --request-id` | 已有 pending ACK 恢复并确认 completed |
| `materials` | `--binding --file --key-id --request-id --intent` | 等待并供给一个真实材料请求，打印受理状态 |
| `material-submit` | `--intent` | 提交原材料响应，打印受理状态 |
| `material-status` | `--intent` | 材料状态为 core-consumed |

不属于该模式的专用参数会被拒绝。`--intent` / `--file` 必须为绝对私有文件路径。三个 store 模式另需 `--key-file` 或 `TANSR_ARCHIVE_KEY_FILE`；文件为 64 个十六进制字符（可带末尾换行），即宿主管理的 32 字节 AES-256-GCM 密钥。密钥不得与档案内容混存、硬编码或丢弃；key-id 只标识密钥，不含密钥材料。

生成一个新的密钥文件示例；仅用于新档案，绝不能覆盖恢复所需的原密钥：

```python
import secrets
from pathlib import Path
from tansr_sdk.storage import PrivateDirectory

with PrivateDirectory(str(Path.home() / "tansr-demo-keys"), create=True) as directory:
    directory.write("archive.key", secrets.token_hex(32).encode("ascii"), replace=False)
```

```text
tansr-py-archive --mode target --session SESSION_ID
tansr-py-archive --mode sync --binding BINDING_ID --file ABSOLUTE_ARCHIVE_FILE --key-id local-key-1 --key-file ABSOLUTE_KEY_FILE
tansr-py-archive --mode recover --binding BINDING_ID --file ABSOLUTE_ARCHIVE_FILE --key-id local-key-1 --key-file ABSOLUTE_KEY_FILE --request-id ORIGINAL_RECOVERY_ID
```

`sync` 默认最多 64 页，`--max-pages` 范围 1..1024；达到上限但未完成会失败。先验证原页和连续链、耐久保存数据及 pending coverage，再发送 ACK。事件游标、receipt/head、pending coverage、ACK 和材料消费是不同状态；保存文件不等于 ACK 已确认。`recover` 要求原档案存在，仅恢复 pending ACK，不宣称所有剩余页已同步。只有明确 `if_match_stale` 的 stale revision 才允许显式 rebase，仍保留原 operationEpoch；不能对任意 412、busy、过期或撤权换 epoch 重试。

### 材料分块与冷恢复

先运行监听，再让真实 Serve 产生所需材料请求：

```text
tansr-py-archive --mode materials --binding BINDING_ID --file ABSOLUTE_ARCHIVE_FILE --key-id local-key-1 --key-file ABSOLUTE_KEY_FILE --request-id response-one --intent ABSOLUTE_RESPONSE_FILE
tansr-py-archive --mode material-status --intent ABSOLUTE_RESPONSE_FILE
```

SDK 只从已验证档案供给请求点名的材料。Demo 先保存 `.request` 及 `.owner`，将原 remaining TTL 固定为绝对截止；分块上传前再保存 `.identity` 中的原 response requestId/operationEpoch/截止，最后保存精确响应意图及其 `.owner`。冷恢复重用同一组文件、身份和原截止；不会重新获得 TTL、换键或覆盖旧意图。

`materials` / `material-submit` 退出 0 可能只表示 `received`；这不是核心已使用材料。`material-status` 只有 `core-consumed` 才退出 0；`received`、超时或未知均不能写成消费完成。意图过期后仍可用 status 模式查询原事实，不能当作新写入授权。

### 档案、记忆与缓存的区别

`FileStore(path, key, key_id, identity, check_access)` 负责单端加密档案，identity 从真实 binding/status 通过 `identity_from_binding` 得出。每次访问仍核验当前身份；本地密文、旧票据或备份不授予权限。自定义 `ArchiveStore` 可以接入开发者的介质，但必须遵守同一验证、原子耐久、pending/coverage 分离和取消提交边界。Python 介质格式不直接兼容其他 SDK 私有文件格式，不能重命名外来文件导入。

长历史与点名材料由 Python 端保管/供给，材料的采用、压缩和上下文组织仍在 Serve。首版没有独立 `MemoryClient` 或完整记忆发布/同步宿主；`terminal.memory.read`、`terminal.memory.command`、`terminal.memory.receipt` 可通过通用 `Client.call` 消费服务已授权的记忆能力，不能把 `FileStore` 宣传成完整记忆数据库。缓存的 `cache.*` 同样是冻结低层操作，高层自动缓存续接不在本包首版承诺内。

例如读取已有会话的记忆状态，使用 `api.call("terminal.memory.read", CallOptions(parameters={"id": session_id}))`；`CallOptions` 从 `tansr_sdk` 导入。写入需按原 schema 携带真实 revision、requestId 和授权上下文，不能照抄另一个会话的数据。配置/记忆/缓存功能是否可用，仍取决于 Serve 的装配与协商，不由客户端自行解锁。

## 同步、asyncio 与资源生命周期

三个 console 命令采用同步公开接口；另有实际可运行的异步单轮示例：

```text
python -m tansr_demo.async_chat --message "你好"
python -m tansr_demo.async_chat --attach ID --message "你好"
```

异步示例要求 idle 会话和 `--message`，不接受创建意图模式；权限/提问需交互接入。已有事件循环的应用直接 await SDK，不嵌套 `asyncio.run`。以下完整脚本只依赖 SDK，不导入 Demo；它复用上文已签发的私有 token/scope 文件，另需 `TANSR_SESSION_ID`。若为 offload，再显式设置 `TANSR_SESSION_FAMILY=sdk2-offload-v1`（这是本示例读取的环境变量，不是 Client 隐式配置）：

```python
import asyncio
import os
from pathlib import Path
from tansr_sdk import AuthToken, Client, Error, strict_json
from tansr_sdk.session import AsyncSessionClient, SessionClient
from tansr_sdk.storage import PrivateDirectory

def token_provider(cancel):
    cancel.check()
    token_file = Path(os.environ["TANSR_TOKEN_FILE"])
    scope_file = Path(os.environ["TANSR_SCOPE_FILE"])
    if token_file.parent != scope_file.parent:
        raise Error("invalid_input")
    with PrivateDirectory(str(token_file.parent)) as directory:
        scope = strict_json.loads(directory.read(scope_file.name, max_bytes=8192))
        fields = {"applicationScopeId", "endUserId", "authorizationRevision"}
        if (not isinstance(scope, dict) or set(scope) != fields or
                any(not isinstance(value, str) or not 1 <= len(value) <= 128
                    for value in scope.values())):
            raise Error("invalid_input")
        token = directory.read(token_file.name, max_bytes=8192).strip(b"\r\n").decode("ascii")
        if strict_json.loads(directory.read(scope_file.name, max_bytes=8192)) != scope:
            raise Error("permission")
    cancel.check()
    principal = strict_json.dumps({key: scope[key] for key in sorted(scope)}).decode("utf-8")
    return AuthToken(token, principal)

async def read_async(api, session_id):
    async with AsyncSessionClient(api) as sessions:
        session = await sessions.attach(session_id)
        return await session.history(0, 0)

with Client(os.environ["TANSR_BASE_URL"], token_provider,
            family=os.environ.get("TANSR_SESSION_FAMILY", "sdk1")) as api:
    session_id = os.environ["TANSR_SESSION_ID"]
    print(SessionClient(api).attach(session_id).history(0, 0))
    print(asyncio.run(read_async(api, session_id)))
```

provider 的稳定 principal 取自可信 scope；每次读取新 token 后 Client 仍核对 principal，变更时拒绝复用旧 Client。生产应用可替换此函数接入自己的认证系统，无需复制 Demo 文件管理。不要将 Serve 的上游模型密钥交给终端。

同步流调用 `session.events(last_event_id, cancel=..., deadline_ms=...)`，使用 `with stream` 并在发送前取 `session.meta().last_seq` 创建 `TurnTracker(floor)`；发送受理后持续将事件交给 `tracker.observe(event)`，以匹配的 `Outcome.status` 判断本轮结果。异步写法是 `async with await session.events(...) as stream` 和 `async for event in stream`，不能省略前面的 await。`TurnTracker.from_replay(floor)` / `TurnTracker.resume(floor, turn_id)` 用于已在运行的原轮；gap 时先对账，不能把较旧的完成事件当新轮成功。完整可执行流程见 [同步 chat](https://github.com/tansrai/tansr-python/blob/main/demo/src/tansr_demo/chat.py) 和 [异步 chat](https://github.com/tansrai/tansr-python/blob/main/demo/src/tansr_demo/async_chat.py)。

`Client` 默认总在途 `max_pending=64`（范围 1..4096，含 provider 和流）；超帽抛 `capacity`。`AsyncClient` 控制池默认 4 worker/16 pending，流池 4/8；`AsyncSessionClient` 控制池 4/16、流池 2/8。默认 HTTP 传输最多 16 连接、8 长流，为控制请求留位。Demo 事件交付队列上限 16；各预算独立，不能相加理解为服务端并发保证。

`AsyncArchiveClient(client, bridge=None, *, stream_workers=2, max_stream_pending=8, storage_workers=2, max_storage_pending=8)` 将短控制、长流和磁盘工作分开。自建短控制桥默认 4/16；流建立/读取默认 2/8；`prepare_materials`、`prepare_materials_before`、`sync_once`、`recover_pending` 走独立存储池 2/8。传入 `bridge` 只替换短控制桥，属于借用；`aclose()` 不关闭该借用桥，但会收回自己拥有的流/存储池，并等待本实例工作实际结束。扩池不能改变服务授权、原截止或介质提交顺序。

异步桥每次提交工作时捕获调用 task 的 `contextvars.Context`；回调对 ContextVar 的赋值不串到宿主或下一次请求。Runner 的观察/续租线程继承当前执行上下文，OutputWriter 固定使用构造时的 owner context，后续 producer 不能借其线程身份替换输出归属。这是 Python 标准浅复制，不会深复制 ContextVar 中的可变对象；宿主仍须在每次 provider/authorize 中验证当前 scope，不能把上下文传播当作授权快照或撤权替代。

`Client(transport=...)` 接管注入传输的关闭。`AsyncClient(base_url, provider)` 自建并拥有 Client；`AsyncClient(client=existing_client)` 借用已有 Client，只关闭自己的桥、流和请求 token。高层 `AsyncSessionClient` / `AsyncExecutorClient` / `AsyncArchiveClient` 借用同步入口，关闭自己的调度和观察资源，不关闭宿主共享 Client 或发送 interrupt。

流须用 `with` / `async with` 或显式 close/aclose。`close(timeout)` / `aclose(timeout)` 返回 False 表示仍有 pending 工作，不是已关闭；保留依赖并等待真正收敛。取消 Future 不会杀死 Python 线程，也不撤销已发远端请求或已耐久的本地事实。业务 handler 必须合作取消；async 对象不能跨 event loop 使用。

工具端提供 `AsyncExecutorClient`、`AsyncRunner` 和 `adapt_async_handler`；档案提供 `AsyncArchiveClient`。Session 还提供多模态 `send_blocks`、输入状态、检查点原始字节导入导出、compact/cwd 及 transcribe/speak 请求。Demo 展示的文字对话不覆盖全部 API；音频请求不自动录音、播放或发送转写文本，HTTP 200 也不能替代响应内容验证。

`Session.close()` / `await AsyncSession.close()` 是**远端结束会话**的写操作；`Client.close()`、异步 facade 的 `aclose()`、事件流 close 和 `Runner.close()` 是本地资源收回，不能互换。建议先停止提交，再关闭流与 runner/facade，待磁盘/handler 真正结束后释放 journal、档案和最终 Client。`AsyncRunner.aclose()` 还会停止其包裹的同步 Runner，因此只把准备交由它停止的 Runner 传入。

## 错误和故障诊断

捕获公开 `tansr_sdk.Error`。本地校验/容量/取消类在 `code`；统一服务错误的 `code` 通常为 `http`，进一步读取 `http_status`、`wire_code`、`retry_action`、`request_id`、`retry_after_ms`。`detail` 可保留原 domainCode/reason，供逻辑分支使用，不应未经脱敏写入日志。不要只以 HTTP 状态推断副作用。

| 现象 | 先检查 | 正确后续 |
| --- | --- | --- |
| `ModuleNotFoundError` / 命令找不到 | venv 完整解释器路径、`python -m pip show tansr-sdk tansr-sdk-demo`、是否安装 Demo 包 | 用同一个解释器运行 `python -m tansr_demo.chat --help`；不把开发树加到生产 PYTHONPATH |
| 无适配 wheel / 依赖冲突 | Python 补丁、CPU/OS、requirements marker、同版 SDK/Demo | 使用已核验的目标 wheelhouse；不禁依赖检查或假装纯 Python 包没有原生密码依赖 |
| `unsupported_tls_runtime` / TLS 失败 | 该解释器实际 `ssl.OPENSSL_VERSION`、可信发行来源、域名及 CA | 保留 guard；按发行说明选择已验证隔离运行时，不能关闭证书验证 |
| `credentials_state_overlap` / `permission` | 凭据与状态目录、scope 当前值、私有 ACL/所有者与路径替换 | 分开目录；身份改变新建 Client；不放宽到所有用户可写 |
| `http` + 401/403 | 当前短 token、稳定 principal、应用能力和服务授权 | 由宿主重新认证/恢复授权；相同主体续票不等于许可重发未知写入 |
| 202 后无文本 / stream EOF / replay gap | 原 session/turn、SSE 代理缓冲或空闲超时、游标和服务状态 | 重接同一会话并核历史/状态；不得自动新建或重发消息 |
| `capacity` / `not_quiescent` / 关闭返回 False | 未释放流、慢 handler/provider、未结束磁盘事务、各自 pending 帽 | 停止新提交，合作取消并等待实际结束；不假称线程/事务已回滚 |
| 网络/timeout/result_unknown/commit_unknown | 原 request key/body/deadline、journal/意图/远端状态 | 先查询原结果；不可改键、删目录或延长原 TTL 重做业务 |
| stale revision / 412 | 服务返回的 domainCode/reason、原 binding/epoch | 仅明确合法条件下 `recover_pending` 显式 rebase；普通 sync 不自动迁移 |
| `received` 但未 `core-consumed` | 原材料 request、状态和核心调度 | 保留原档案及响应意图，查 material-status；不提前推进消费或释放材料 |
| 密文认证失败 / key-id 错 / 档案格式未知 | 原 key、文件、owner、介质版本和备份来源 | 保留原件，恢复正确密钥/文件；不清档、不换 key 冒充恢复 |

`Client.call` 不自动重试。`retry_same_request(operation, options, previous)` 只接受**同一 Client** 产生的原错误、明确 `same-request` 提示和同一请求指纹，保留原 key/body/条件/绝对截止；修改错误证据、换主体或延长截止会被拒绝。unknown/commit_unknown 应查询原状态，不能调用此方法盲重发。普通 401 也不会自动刷新后重放写入。

公开参数包含“缺省”和“显式 null”两种不同含义；不要随手把未填写的字段都变成 None。SDK 的 `strict_json` 保留数值词法，但解析再编码不保留所有原始空白等字节。需要原字节重放时保存并复用原 bytes，不用 `json.dumps` 或另一种编码替换档案/签名控制体。私有 journal、意图和档案不是可随意合并编辑的配置文件。

## 验证与剩余边界

正常运行使用包内生成的 81 操作和 schema，应用不需要合同源文件或生成器。公开源码检查显式使用 `--mode public`，校验仓库中的公开合同清单。私有服务夹具和开发历史不是运行包内容。发行产物应核对版本、来源与哈希。

局部 Demo 测试使用合成会话/事件/存储，覆盖参数、身份、失回、终态、分块和 received 边界。另有集成验证使用实际 Serve 核心与合成身份、平台和模型，不宣称调用真实付费模型。完整回归、Windows/Linux/macOS 的已测组合、wheel/sdist 独立消费和发布是分别验证的事项；发行说明列出已验证组合及限制，不外推到未测环境。
